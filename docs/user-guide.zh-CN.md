# 瞬谱光电 OKR 用户指南（简体中文）

瞬谱光电 OKR 用于管理公司 Objective、关键结果（KR）、日报、实际进度和工作工时。界面第一次打开时默认显示中文；顶栏可即时切换到 English，链接地址不会改变。系统界面会翻译，Objective、KR 和日报等用户输入的业务内容不会被自动翻译。

## 1. 登录与可见范围

登录后，系统会根据你的组织、角色、项目成员关系和数据密级显示内容。请不要通过浏览器地址猜测或共享受限项目：无权访问的项目不会出现在员工或 HR 的项目列表中，也不会显示项目名称、数量、密级、描述或占位卡片。若直接打开无权资源的链接，只会看到不泄露资源信息的通用拒绝访问页面。

- 员工可以查看自己被授权的项目和自己负责的 OKR；只能更新自己负责 KR 的实际进度，并为自己负责的 KR 或目标创建、编辑、解决风险事件。
- 项目负责人（Project Leader）可以查看和管理自己负责项目中的项目级风险事件，并维护计划进度和里程碑；不能替员工修改员工记录的实际进度。
- HR 没有通用项目风险管理权限，也不会从项目列表得知未获授权项目的任何元数据。

## 2. 更新我的 KR：真实、可追溯的实际进度

在“OKR 管理”选择“更新我的 KR”。选择你负责的 KR，填写 **0–100** 的实际完成百分比、有效日期和更新说明，然后保存。

- 这是正常保存，不是模拟预览，但只有在正确配置了 `VITE_APP_MODE=supabase`、有效 Supabase URL 和公开 publishable/anon key 的生产环境中，保存才会调用受限后端接口并写入 Supabase。演示模式是不可持久化的本地预览，不能作为真实保存的证明。
- 每次成功保存都会追加一条不可变的 KR 进度记录，保留日期和说明；不会覆盖过去的历史记录。
- 只有 KR 负责人能提交实际进度。无效百分比、没有日期或说明、网络失败或权限不足都不会创建记录；修正后重新提交即可。
- 保存后页面会重新读取数据。系统将实际进度与计划进度、里程碑、截止日期和未解决风险一并计算执行状态。

### 计划进度与实际进度

计划进度是项目负责人用于排期和预测的基线；实际进度是 KR 负责人在更新时记录的事实。这两项不同，差额只是在执行状态计算中使用，并不会改写员工的实际进度历史。

## 3. Daily OKR 日报

每位员工每天只有一份日报。每个 Daily OKR Entry 分别记录今日目标、关联 Objective、关联 KR、工作描述、结果/数据、条目附件和工时。再次保存同一天日报时更新原日报并保留修订记录，不会新建重复日报。

## 4. Objective 与 KR 协作

管理层创建季度 Objective 并分配项目负责人；项目负责人不能修改 Objective，只能在被分配的 Objective 下创建 KR。KR 负责人可从组织内所有已启用且已批准的员工中选择，分配后系统自动将其加入项目团队。

## 5. 权限与数据可见性

管理员只维护用户与角色；管理层查看公司 Objective、KR 进度、项目负责人、项目进度和员工已记录工时；员工查看自己参与的 Objective、被分配的 KR、进度和日报。

## 6. 切换中文与 English

点击顶栏的“中文 / English”可即时切换，页面不会跳转也不会改 URL。首次访问默认中文。登录前，选择保存在本机；登录并读取个人资料后，个人偏好优先并会安全地写回你的资料。若偏好保存暂时失败，界面仍会立即切换，稍后可再次选择语言。

## 7. 日报、证据与附件

按页面提示填写结构化日报和证据。仅上传与你有权处理的材料；附件受权限、文件类型和大小限制保护。HR 或未授权人员不应看到受保护附件的文件名、数量、路径或下载链接。上传失败时先检查文件类型、大小和网络，再使用页面的重试或替换操作。

## 8. 常见问题与支持

- **保存 KR 失败：** 确认该 KR 是你的、百分比在 0–100、日期与说明已填写；保留表单内容后重试。
- **看不到项目：** 这通常是授权范围，而不是系统故障。项目列表不会显示无权项目。请向项目管理员申请成员关系或授权，不要共享截图或猜测项目名称。
- **准备上线或迁移：** 参阅 [Supabase 与阿里云上线手册](supabase-setup.md)。迁移和线上部署必须先经过明确批准、备份和本地验证；不要把 service-role key、数据库密码或用户令牌放入前端或日志。
