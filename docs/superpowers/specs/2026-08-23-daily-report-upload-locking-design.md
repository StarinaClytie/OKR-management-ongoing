# 日报附件上传与锁定规则设计

## 目标

修复日报附件上传失败与残留 `pending` 记录阻塞提交的问题，并让上传状态、密级权限和日报锁定规则对用户清晰可见、由前后端共同强制执行。

## 已确认的业务规则

### 附件上传

- 用户选择成果附件后立即开始上传，不等待点击“提交日报”。
- 每个附件独立显示真实上传进度条和百分比。
- 文件上传完成并通过服务器最终校验后显示“上传完成（100%）”。
- 任一附件处于等待、上传中、失败、删除中或校验中时，“提交日报”按钮不可用。
- 上传失败必须显示明确状态，并提供“重试”和“移除”。
- 用户取消编辑、移除附件或上传失败时，系统清理本次未完成的对象与 `pending` 元数据。
- 历史遗留或中断产生的 `pending` 记录不得永久阻塞当天日报；开始新的编辑会话时，由服务器安全废弃不属于当前上传会话的未完成记录。
- 防止重复点击或并发操作为同一文件创建多条附件记录。

### 存储架构

- 浏览器继续通过 `https://api.okr.trspectra.com/storage/v1/...` 使用 Supabase Storage。
- 阿里云 OSS 可作为底层对象存储，但不直接绑定 `okr.trspectra.com`，也不向浏览器暴露永久访问密钥。
- 数据库只接受服务器签发、属于当前用户和当前日报的附件路径。
- 上传完成后继续校验 MIME、文件大小、附件身份和所属日报；放宽上传阶段的兼容性检查不能降低最终校验强度。

### 密级

- 角色与安全许可分离。管理员为用户配置安全许可级别。
- 默认可采用：普通员工和项目负责人为“内部”，管理层可配置“机密”或“绝密”；最终以管理员配置为准。
- 附件密级不得超过当前用户的安全许可。
- 前端隐藏或禁用超出许可的密级选项，并解释原因；数据库继续强制校验，防止绕过前端。

### 日报编辑与锁定

- 用户每天只能有一份日报，多次保存更新同一记录并形成版本历史。
- 未审核的当日日报可以继续编辑。
- 管理层审核/确认后立即锁定，不得再次修改。
- 未审核日报在公司时区 `Asia/Shanghai` 跨过次日零点后自动锁定。
- 锁定规则同时应用于前端入口和数据库写入；直接调用 API 也不能修改已锁定日报。
- 历史日报展示“已锁定”，保留只读查看和附件下载能力。

## 交互流程

1. 用户填写 Daily OKR，并选择一个或多个成果附件。
2. 前端为当天日报取得或创建唯一草稿外壳，并开始附件上传会话。
3. 每个附件依次经历：`等待上传 → 上传中（百分比） → 服务端校验中 → 上传完成`。
4. 上传失败时，该附件显示失败原因；用户可重试或移除，其他已完成附件不重复上传。
5. 只有表单必填项有效且所有选中附件均为“上传完成”时，提交按钮启用。
6. 提交时只关联已经完成的附件身份并创建新的不可变日报版本，不再次上传文件。
7. 提交成功后，当天仍可编辑；审核确认或跨日后变为只读。

## 数据与接口边界

- 附件增加可识别当前上传会话的标识，服务器只能清理调用者自己的未完成会话。
- 提供显式的“开始/恢复日报草稿”“开始附件上传”“完成附件上传”“放弃未完成上传”“提交日报版本”边界。
- 提交接口只检查本次请求显式关联的附件，不因无关的历史 `pending` 记录失败。
- 所有写接口在数据库中检查：组织、作者、日期、审核状态和公司时区锁定状态。
- 上传进度由浏览器实际传输字节计算；数据库的 `uploaded` 状态只在对象存在且元数据校验通过后写入。

## 错误处理

- Storage/RLS、网络超时、文件类型、文件大小、密级不足和日报锁定分别映射为可理解的中文提示。
- 页面离开或刷新后，重新加载服务器状态：已完成附件恢复为 100%，未完成会话可安全废弃后重试。
- 提交按钮在请求进行中保持禁用，阻止双击和并发提交。

## 测试范围

- 附件选择后立即上传，并按字节更新进度。
- 0%–99%、校验中、失败状态均不能提交；全部 100% 且校验完成后可以提交。
- 上传失败后重试不会产生重复有效附件；移除会清理 pending 记录。
- 历史 pending 不阻塞无附件提交或新的上传会话。
- 用户无法选择或提交超过自身许可的密级。
- 当日日报可编辑；审核后不可编辑；次日零点后不可编辑。
- 同一用户同一天始终只有一份日报，重复保存更新已有记录。
- Storage 上传、最终校验、下载和删除继续遵守组织隔离及 RLS。

## 不在本次范围

- 浏览器直接使用 OSS AccessKey。
- 给 OSS 配置独立公开下载域名。
- 跨日解锁或管理员代改历史日报；如未来需要，应设计独立、可审计的更正流程。
